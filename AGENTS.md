## Hard constraints (carried from planning — still apply when code lands)

- `@openuidev/vue-lang` is 0.4.x and early-stage; it does **not** match the React renderer / OpenUI Lang 1.0 feature set (some action features missing). Isolate OpenUI behind our own adapter/public API; never expose renderer types as the framework contract.
- Nitro/server code must consume **serializable** component definitions (Zod schemas; `zod/v4`) and must never import Vue SFCs or client-only library modules. Vue component imports stay on the client side.
- Strict component allowlist; never evaluate model-generated JavaScript or Vue templates; privileged/business actions go through explicit, server-authorized tools.
- OpenUI Lang positional arguments follow **Zod object property order** — reordering/reshaping a schema breaks the wire format.
- Keep OpenUI behind our public APIs so the 0.4.x renderer can be swapped/upgraded.
- **SFC props contract (hard rule, learned the hard way):** never snapshot `const p = props.props`. The renderer reuses and patches the same component instance while a program streams, so a setup-time snapshot freezes the first (usually empty) `children` array and the card body never fills in. Always `const p = computed(() => props.props ?? {})`, use `p.value.x` in script and `p.x` in templates. This applies to every SFC in `packages/components/src/components/`.
- **Field props contract:** form fields call `useGenUIField(() => p.value)` — pass a **getter**, never a snapshot (`useGenUIField(p.value)` freezes `name`/`rules` at setup). The hook watches `name`/`rules`/`defaultValue`, re-registers under a new name and unregisters the old one, so a field the renderer renames mid-stream is submitted under the new name only.
- **Nuxt UI prop contract:** every SFC prop must exist on the installed `@nuxt/ui@4.12.0` component — check `node_modules/.pnpm/node_modules/@nuxt/ui/dist/runtime/components/<Name>.vue` before using one. Known traps: `UInputDate`/`UCalendar` use `minValue`/`maxValue` (not `min`/`max`), `UTable` has no `striped` prop (use the `ui` map), `UTabs` has `modelValue`/`defaultValue` (no `defaultIndex`), and `UTooltip` needs the host `UApp` tooltip provider.
- **Markdown contract:** model-authored markdown goes through `renderMarkdown` (`packages/components/src/markdown.ts`, exported as `@nuxt-ui-genui/components/markdown`). DOMPurify returns its input **unchanged** when there is no DOM, so the helper must keep the fail-closed branch (`if (!DOMPurify.isSupported) return escapeHtml(source)`) — never call `DOMPurify.sanitize` unguarded on a `v-html` path.
- **Action schema contract:** `actionSchema` (in `packages/components/src/action.ts`) must keep the catch-all branch rejecting the builtin types, otherwise `{ type: 'open_url' }` without a `url` parses and the host receives an action it cannot act on.
- **No AI SDK coupling (hard rule, user directive 2026-11-14):** `packages/core`, `packages/components`, `packages/nuxt` and `packages/chat` must never import `ai` or `@ai-sdk/*`. OpenUI is an open standard with many backends (LangGraph, Google ADK, Mastra, AG-UI, OpenUI Cloud, a plain HTTP route), so the framework talks **plain OpenUI Lang text**: `packages/chat`'s `createGenUIChat` takes an endpoint (`createFetchTransport`) or any `GenUITransport` (an async iterable of text), and `packages/core`'s `responseTextChunks` reads `text/plain`, `text/event-stream` and `application/x-ndjson` alike. The AI SDK lives only in the optional adapter `@nuxt-ui-genui/ai-sdk` (`streamGenUI` UI-message-stream, `streamGenUIText` plain text, `createAIChat` in `@nuxt-ui-genui/ai-sdk/chat`). Nuxt UI's chat components are typed against the AI SDK's `UIMessage`, so `GenUIMessage` mirrors that shape exactly (`id`, `role`, `parts[]`, `state: 'streaming' | 'done'`) and a host crosses that one boundary with a cast — the playground app code imports nothing from `ai`.

- **Form payload contract (2026-11-15):** a form submits **only the fields that are its children right now** (`fieldNames` in `packages/components/src/components/Form.vue`, derived from the child nodes' `props.name`). A field the renderer renames, replaces or drops must not travel in `params.values` nor in the action's `formState` — the mirrored values are removed from the renderer store (`setFieldValue(formId, 'Form', name, undefined)`) when the field is unregistered, when it leaves the children, and when the form unmounts. The renderer replaces the node (and therefore the form instance) on a re-parse, so the store outlives the component.
- **Form validation / UForm contract (2026-11-15):** generated field SFCs wrap their visible control in Nuxt UI `UFormField` (with `eager-validation` — without it, Nuxt UI's `deferInputValidation` prevents a visible error from clearing while typing once the field has been surfaced), and `Form.vue` renders Nuxt UI `UForm` rather than a raw `<form>`. The validator is a custom Standard Schema (`form-schema.ts`) wrapping upstream lang-core `parseStructuredRules` + `validate` with only a local `requiredValidator` wrapper for scalar boolean `false`, so the unchecked-checkbox case still shows the documented `Required` message and the validator receives flat `path: [name]` issues. `UForm` runs with `:transform="false"`, `:validate-on` gated empty before the first submit (`submittedOnce` flips on the first `@error`), and `:validate-on-input-delay="0"`, preserving the documented UX: no validation messages before the first submit, and a visible error clears as soon as the value becomes valid. `GenUIFormContext` no longer carries `errors`/`revalidate` (display is owned by `UFormField`/`UForm` via `useFormField()`). Only current field children are validated and submitted; stale fields never travel. Both library factories (`createGenUILibrary`, `createNuxtUILibrary`) expose the upstream `library.toJSONSchema()` — do not replace it with a local schema generator. Upstream `createFormValidation`/`provideFormValidation`/`useFormValidation` remain unused by design.
- **Shipped-artifact contract (2026-11-15):** the plain-Vue entry (`@nuxt-ui-genui/nuxt/vue-plugin`) must not import a raw `.vue` from `node_modules` — a Vite host would need `optimizeDeps.extensions` for that. `GenUIRenderer` is therefore a render-function component (`packages/nuxt/src/runtime/GenUIRenderer.ts`), and both renderers share the `open_url` bridge in `packages/nuxt/src/runtime/action-bridge.ts`. `packages/nuxt` is built by `nuxt-module-build`, which **ignores** a local `build.config.ts` — do not add one (the module builder builds `src/module` and `src/runtime/` itself).
- **Tool provider / parse-hint contract (2026-11-15):** both renderers forward `toolProvider` (plain `Record<name, (args) => Promise<unknown>>` or an `McpClientLike`) and `queryLoader` to vue-lang's `<Renderer>`; a program calling `Query()`/`Mutation()` with no provider renders only its defaults. `initialState` seeds `$state` at mount (no `onStateUpdate` on mount); `Button` forwards the evaluated `Action([@Set(...)])` plan (`{ steps: [...] }`) intact to `useTriggerAction` — never re-flatten such a plan — or the state never updates. `packages/nuxt` tests resolve `@nuxt-ui-genui/components/sfc` to the **built** dist; after touching components run `pnpm build:packages` before `pnpm test`. `pnpm --filter @nuxt-ui-genui/nuxt exec vitest run <file>` does not work ("Command vitest not found") — use `npx vitest run <file>` from `packages/nuxt` (~20 s per file). `meta.unresolved` (refs used but not yet defined) and `meta.orphaned` (dead value statements, excludes `$state`/`Query`/`Mutation`) are distinct fields and both surface in the dev overlay plus host callbacks `onUnresolved`/`onOrphaned`.
- **Child-filter contract (2026-11-15):** a container that accepts a fixed set of children (`Stats` → `StatsCard`, `Buttons` → `Button`, `ChatPalette` → the chat children, `Form` → the field children) drops every child that is not an element node of an accepted type. `Card` is the exception: it is a generic container, so it keeps plain-text children.
